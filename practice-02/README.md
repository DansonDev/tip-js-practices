## Модель и модули

Задача содержит `id`, `title`, `completed`, `priority`. id — положительное безопасное целое число, название — строка длиной 1–100 после trim, приоритет строго low/medium/high. Новая задача имеет completed=false. Ожидаемые ошибки возвращаются как `{ ok: false, error }`, без исключений и без преобразования типов.

- `data.js` хранит неизменённый общий demoTasks и выбранный набор варианта.
- `task-service.js` содержит девять функций, без DOM, консоли и глобального списка.
- `main.js` собирает сценарии, заменяет состояние только после ok=true и форматирует прогресс.
- `task-extra.js` рассчитывает сводку по приоритетам.
- `checks.js` — исходные проверки преподавателя; `own.checks.js` — дополнительные проверки.

Поиск использует find и строгое сравнение. Невыполненные задачи отбираются через filter, названия — через map. Добавление использует spread массива, обновления — map и spread выбранного объекта, удаление — filter. Повторное присваивание того же статуса или названия тоже возвращает новый массив и новый объект. Неизменённые задачи могут разделять ссылки.

## Индивидуальный вариант 3

Тема — создание сайта-портфолио. Шесть задач с id [11,23,37,41,58,64], изначально выполнены 11 и 23. Приоритеты low, medium, high представлены по два раза. Новая задача id=80 имеет low.

| Этап | Ожидание: всего / выполнено / осталось / прогресс | Факт | Итог |
|---|---|---|---|
| Исходное состояние | 6 / 2 / 4 / 33.3% | 6 / 2 / 4 / 33.3% | Пройдено |
| Добавление 80 | 7 / 2 / 5 / 28.6% | 7 / 2 / 5 / 28.6% | Пройдено |
| Повторное выполнение 11 | 7 / 2 / 5 / 28.6% | 7 / 2 / 5 / 28.6% | Пройдено |
| Переименование 23 | 7 / 2 / 5 / 28.6% | 7 / 2 / 5 / 28.6% | Пройдено |
| Удаление 37 | 6 / 2 / 4 / 33.3% | 6 / 2 / 4 / 33.3% | Пройдено |

Повторная установка true для 11 сохраняет количество выполненных, но создаёт новый массив и объект записи. Финальные id: [11,23,41,58,64,80]. Повторное добавление 80 отклонено, состояние и исходный variantTasks сохранены. Общий сценарий и индивидуальный вариант запускаются одной командой.

## Расширение и вывод

`getPrioritySummary(tasks)` принимает корректный массив задач и возвращает все три приоритета, у каждого числовые total и pending. Для demoTasks фактически получено low={1,1}, medium={2,0}, high={1,1}. Для [] все шесть значений нулевые. Для списка только с high: high={4,2}, остальные нулевые. Замороженные входные объекты не меняются.

Освоены возвращаемые значения, параметры по умолчанию, функции обратного вызова, ES-модули и обновление данных без мутации. Копирование массива не копирует вложенные объекты: для обновлённой задачи нужен отдельный spread объекта. Отказ обрабатывается как результат операции и сохраняет текущее состояние.
