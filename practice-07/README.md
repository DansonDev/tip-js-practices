## 1. Цель и результат

Собрать список задач на React из функциональных компонентов и связать его с формой, фильтрами и статистикой. Записи создаются, редактируются, переключаются и удаляются в памяти страницы. Перезагрузка заново создаёт состояние из исходного набора, поскольку ПР7 использует `useState` без внешнего хранилища. [Методичка и стартовый проект ПР7](https://github.com/adyshkins/TIP-JS/tree/37fd64e6f09e728e60e6304d50eda07c398bbd1c/practices/practice-07)

## 3. Компоненты и состояние

| Модуль | Ответственность |
|---|---|
| `App` | Владеет полным массивом, фильтрами, `editingId` и сообщением о результате. По актуальному массиву находит редактируемую задачу. |
| `TaskFilters` | Получает значения фильтров и категории через props. Передаёт наверх новый объект через `onChange`. Сброс отключает все условия. |
| `TaskList` и `TaskItem` | Показывают результат выборки, число найденных записей, статус, приоритет и название категории. Передают id из кнопок наверх. |
| `TaskForm` | Владеет черновиком и ошибками. Проверяет все поля, передаёт нормализованное значение через `onSave`. При отказе сохраняет черновик. |
| `TaskStats` | Показывает всего, выполнено и в работе по полному массиву. |
| `domain/task-service.js` | Чистые операции, валидация, статистика и фильтрация. |

Данные идут из `App` вниз, действия проходят вверх через функции. При изменении массива функциональный `setTasks(previous => ...)` использует актуальный набор. `map` заменяет только изменённую карточку, `filter` создаёт массив без удалённой записи, добавление дописывает новый объект. Для id берётся максимальный id полного набора плюс 1. Подтверждение вызывается перед обновлением состояния.

Выборка и статистика вычисляются при каждом рендере. Условия фильтра объединяются через И. Поиск учитывает вхождение текста после `trim` и приведения регистра. Стабильный `key={task.id}` сохраняет связь карточки с записью, а смена ключа формы между id и режимом создания инициализирует подходящий черновик. При смене только фильтров этот ключ сохраняется.

## 6. Контрольные вопросы

1. JSX — синтаксис описания элементов React. Сборка преобразует его в вызовы, возвращающие элементы, а значения можно подставлять как JavaScript-выражения.
2. Props передаются родителем. Состоянием владеет компонент и обновляет его через setter.
3. Обычная переменная не инициирует рендер и локальное значение создаётся заново при следующем вызове компонента.
4. Функциональный setter нужен, когда следующее значение вычисляется из предыдущего, в том числе при пакетном обновлении React.
5. Поверхностная копия массива сохраняет ссылки на объекты. Изменение общего объекта затронет предыдущий снимок.
6. Стабильный ключ связывает экземпляр с записью при изменении порядка, фильтрации и удалении. Индекс может перейти к соседней задаче.
7. Они однозначно вычисляются из задач и фильтров. Отдельное хранение создало бы риск рассинхронизации.
8. Дочерний компонент вызывает функцию из props, например `onEdit(id)`.
9. Управляемое поле получает `value` из состояния, а `onChange` меняет это состояние.
10. `select.value` возвращает строку. В задаче categoryId числовой, поэтому значение преобразуется и сверяется со справочником.
11. Смена ключа размонтирует предыдущий экземпляр, и новый инициализирует черновик из нового initialTask.
12. Функция обновления должна быть чистой. React может вызвать её повторно, поэтому диалог выполняется в обработчике до обновления.
13. Если `stats.total` равен нулю, записей вообще нет. Если он больше нуля, а выборка пустая, записи скрыты условиями.
14. `npm test` проверяет предметные функции, границы и неизменяемость. JSX, фокус и события проверяются через Chrome.
15. Источник задач и id переносится на API. Понадобятся эффект загрузки, состояния сети и асинхронный `onSave` с подтверждением сервером.
