## 1. Цель и результат

Подключить React-задачник к серверу. Чтение задач и категорий выполняется эффектом, создание, редактирование, смена статуса, удаление и сброс набора — по действию пользователя. После успешной записи приложение перечитывает выборку с текущими фильтрами. [Методичка и стартовый проект ПР8](https://github.com/adyshkins/TIP-JS/tree/37fd64e6f09e728e60e6304d50eda07c398bbd1c/practices/practice-08)

## 2. Запуск

macOS 27.0.1, Node.js 24.21.0, npm 11.19.0, React 19.3.0, Vite 7.3.6 и Google Chrome 157.0.8103.80.

```bash
cd practice-08
npm ci
npm run api
```

В другом терминале из этой же папки запустить `npm run dev`. Адрес приложения — <http://127.0.0.1:5173/>, адрес API — <http://127.0.0.1:5505/api>. Для проверки сборки выполнить `npm run build` и `npm run preview`.

## 3. Как устроено приложение

`App` владеет фильтрами, снимком задачи для редактирования и сообщением об успешном изменении. Снимок позволяет продолжать редактировать запись, скрытую фильтром. Компоненты показывают поля, ошибки и результат последнего запроса. В ПР8 форма ожидает `Promise<boolean>` от `onSave`; при `false` хранит черновик, при `true` очищает его или выходит из редактирования. Идентификатор новой записи назначает API.

`useTaskData` владеет последним успешным снимком, двумя независимыми ошибками и состояниями загрузки и записи. `task-api.js` формирует предметные запросы и проверяет данные ответа. `api-client.js` выполняет HTTP, нормализует ошибки и обрабатывает 204 без JSON. Объект API создаётся в `config.js` на уровне модуля, поэтому ссылка стабильна.

### Загрузка и отмена

Эффект зависит от `api`, четырёх примитивных полей `q`, `completed`, `priority`, `categoryId` и счётчика `revision`. Он вызывает `loadInitialData` для задач и категорий, сохраняет предыдущий снимок во время загрузки, в cleanup отменяет собственный контроллер. После `await` и в обработке ошибки проверяется `signal.aborted`, поэтому результат от отменённого эффекта игнорируется даже при транспорте, который не прерывает Promise. Свежий эффект может записать новый снимок и статус. Служебный эффект заново устанавливает признак монтирования в каждом setup, в том числе в StrictMode.

### Мутации и два результата

`mutate` сразу сохраняет свой контроллер в ref, ещё до ожидания. Синхронный повтор получает `false`. Мутация использует отдельный сигнал, освобождает только свой контроллер и отменяется при размонтировании. На подтверждённый успех возвращается `true`, меняется `revision`, затем чтение запускается с актуальными фильтрами.

`mutationError` описывает не подтверждённую запись. `error` описывает неудачное чтение. Когда сервер подтвердил POST, а следующее чтение не прошло, остаются сообщение об успешном сохранении и отдельное сообщение о проблеме обновления. Пользователь может повторить GET.

## 6. Контрольные вопросы

1. Рендер должен вычислять интерфейс. Эффект связывает React с сетью и привязывает запрос к жизненному циклу.
2. Cleanup выполняется перед повторным setup с новыми зависимостями, при размонтировании и при проверочном цикле StrictMode.
3. Эффект должен вернуть функцию очистки или ничего. `async` вернул бы Promise, поэтому асинхронная функция объявлена внутри.
4. Нужны API, примитивы фильтров и ревизия. Снимок является результатом загрузки; его включение запустило бы лишний запрос после каждого ответа.
5. Новая ссылка означала бы изменение зависимости каждого рендера и повторную загрузку.
6. Транспорт может завершить Promise после отмены. Проверка состояния сигнала перед обновлением защищает от запоздавшей записи.
7. Старая ошибка может появиться после успеха нового запроса. Проверка отмены применяется и в catch.
8. StrictMode повторно выполняет setup/cleanup в dev, чтобы обнаружить утечки, устаревшие запросы и необратимые побочные действия.
9. State обновляется пакетно. Два обработчика могут увидеть прежний pending; ref меняется сразу.
10. Сервер подтвердил сохранение. Ошибка следующего GET означает, что список ещё не обновлён.
11. Тайм-аут оставляет результат неопределённым: сервер мог создать запись. Повторный POST способен создать дубликат.
12. Фильтр задаёт только выборку. Действие записи относится к выбранной задаче и может завершиться независимо.
13. Отмена останавливает ожидание клиента; сервер мог уже применить запрос.
14. `meta.total` показывает размер текущей отфильтрованной выборки.
15. Реальный CORS, Network, throttling, блокировка запроса, клавиатура, отображение и production-сборка требуют проверки в браузере.

## 7. Вывод

Страница перечитывает серверные данные после мутаций, сохраняет черновик при сбое и показывает отдельно результат записи и чтения. Отмена эффектов и блокировка в ref проверены автоматическими сценариями и в Google Chrome.
